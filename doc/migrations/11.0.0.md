# Migration guide: <11.0.0 to >=11.0.0

11.0.0 **reverts** the API changes from [7.0.0](7.0.0.md) and [9.0.0](9.0.0.md). Using translations without a `BuildContext`, and managing `Localization` instances yourself, made apps harder to maintain than the `Localizations` approach Flutter already provides. The other changes from those releases (`sprintf`, plurals, dependency updates) stay.

If you are upgrading from a version below 7.0.0, nothing changes for you. If you are on 7.x–10.x, undo the steps from those guides:

## 1. Read translations through the context again

```dart
// 7.x – 10.x
LocaleViewModel.localizationInstance.greeting;

// >= 11.0.0
Localization.of(context).greeting;
```

## 2. Change the locale by replacing the delegate

`Localization.load(...)` is no longer how the app switches language. Give your `MaterialApp` a `LocalizationDelegate` and replace it when the locale changes:

```dart
// 7.x – 10.x
await Localization.load(
  locale: locale,
  localizationOverrides: customLocalizationOverrides,
);

// >= 11.0.0
localeDelegate = LocalizationDelegate(
  newLocale: locale,
  localizationOverrides: customLocalizationOverrides,
);
notifyListeners(); // rebuild the MaterialApp with the new delegate
```

```dart
MaterialApp(
  localizationsDelegates: [
    viewModel.localeDelegate,
    GlobalMaterialLocalizations.delegate,
    GlobalWidgetsLocalizations.delegate,
    GlobalCupertinoLocalizations.delegate,
  ],
  locale: viewModel.localeDelegate.activeLocale,
  supportedLocales: LocalizationDelegate.supportedLocales,
);
```

The full setup is described in the [Flutter writer guide](../flutter-writer.md).
