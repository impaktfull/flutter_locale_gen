# Migration guide: <13.0.0 to >=13.0.0

13.0.0 adds [ICU MessageFormat](../translation-formats.md#icu-messageformat) support. Detection is automatic and happens per key, so the upgrade is a no-op for most projects. It is a major version because a handful of strings that used to be plain text are now treated as MessageFormat, which changes their generated Dart signature.

## 1. Check for strings that are now MessageFormat

A value is treated as MessageFormat when it contains any of:

| Marker                      | Example                   |
| --------------------------- | ------------------------- |
| `{` followed by a letter/`_` | `"Tap {button} to go on"` |
| An escaped brace `'{'` `'}'` | `"Use '{' to open"`       |
| Two single quotes `''`      | `"It''s here"`            |

`{` followed by a digit (`"Value {0}"`) is **not** a marker.

This is what the same JSON generates before and after (Flutter writer):

```json
{
  "braces_word": "Tap {button} to continue",
  "two_quotes": "It''s here",
  "quoted_brace": "Use '{' to open"
}
```

```dart
// 12.x
String get bracesWord => _t(LocalizationKeys.bracesWord);
String get twoQuotes => _t(LocalizationKeys.twoQuotes);
String get quotedBrace => _t(LocalizationKeys.quotedBrace);

// 13.x
String bracesWord({required String button}) => _mf(LocalizationKeys.bracesWord, args: {'button': button});
String twoQuotes() => _mf(LocalizationKeys.twoQuotes, args: const {});
String quotedBrace() => _mf(LocalizationKeys.quotedBrace, args: const {});
```

To find affected keys, run this from your project root before upgrading:

```shell
grep -nE "\{[A-Za-z_]|'\{'|'\}'|''" assets/locale/*.json
```

For every hit, pick one:

- **It really is a placeholder.** Keep it and update the call sites: `localization.bracesWord` → `localization.bracesWord(button: 'Next')`.
- **The braces are literal text.** Escape them the ICU way (`"Tap '{'button'}' to continue"`) and change call sites from `localization.key` to `localization.key()`.
- **`''` was meant to show two quotes.** ICU renders `''` as a single `'`. Use `''''` for a literal `''`, or rewrite the string.

## 2. Add `intl` to your dependencies

Generated code imports `package:intl` as soon as one key uses MessageFormat (or a JSON-object plural). Add it next to `sprintf` if it is not there yet:

```yaml
dependencies:
  intl: ^0.20.2
  sprintf: ^7.0.0
```

## 3. Keep placeholder names identical across locales

The generator now compares every MessageFormat key against the default language and prints a warning when a translation uses a different placeholder name or ICU type, for example `{name}` in English and `{naam}` in Dutch. Generation still succeeds, but that translation will not substitute at runtime. Fix the translation file when you see:

```
[locale_gen] Warning: key "greeting" — locale "nl" uses params [naam]; default language "en" uses [name]. ...
```

## 4. `getTranslation` is sprintf-only

`Localization.getTranslation(key, args: [...])` still exists, but for a MessageFormat key it returns the raw template (`"Hi, {name}!"`). Call the generated typed function instead.

## 5. Dart writer (`output_type: dart`)

The Dart writer also understands MessageFormat. If your non-Flutter project formats dates or times in a locale other than `en`, call `initializeDateFormatting()` from `package:intl/date_symbol_data_local.dart` before reading those translations. See the [Dart writer guide](../dart-writer.md).
